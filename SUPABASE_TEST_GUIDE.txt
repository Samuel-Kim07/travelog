Travelog Supabase 테스트 안내
============================

이번 버전은 모바일에서 발생한 "email rate limit exceeded" 문제를 막기 위해
자동 이메일 가입 fallback을 제거했습니다.

왜 수정했나요?
- Supabase Anonymous Auth가 꺼져 있거나 사용할 수 없을 때,
  이전 버전은 앱이 자동 테스트 이메일 계정을 만들려고 했습니다.
- 모바일에서 출간을 여러 번 시도하면 Supabase 이메일 발송/가입 제한에 걸려
  "email rate limit exceeded" 오류가 발생할 수 있습니다.

이번 버전의 동작
----------------
1. 기존 Supabase 로그인 세션이 있으면 그대로 사용합니다.
2. Anonymous Auth가 켜져 있으면 익명 세션을 사용합니다.
3. Anonymous Auth가 실패하면 자동 이메일 가입을 하지 않습니다.
4. 출간/구매/오프라인 다운로드처럼 서버 쓰기 권한이 필요한 순간,
   Supabase Dashboard에서 미리 만든 테스트 계정 이메일/비밀번호를 입력받습니다.

테스트 계정 만드는 방법
----------------------
Supabase Dashboard > Authentication > Users > Add user 로 이동합니다.
테스트 이메일과 비밀번호를 하나 만듭니다.
가능하면 Auto Confirm / Confirm user 옵션을 켜서 이메일 인증 없이 바로 로그인되게 만듭니다.

앱 테스트 방법
-------------
1. GitHub Pages에 새 zip 파일 내용을 업로드합니다.
2. 모바일 브라우저 캐시를 새로고침합니다.
3. 앱에서 최종 출간하기를 누릅니다.
4. Supabase 테스트 계정 이메일/비밀번호 입력창이 뜨면,
   Dashboard에서 만든 계정을 입력합니다.
5. 출간이 진행되는지 확인합니다.

주의
----
- service_role key, database password, JWT secret은 절대 앱 코드나 GitHub에 넣지 마세요.
- Publishable key/anon key만 프론트엔드에서 사용합니다.
- 유료 코인 차감은 정식 운영 전 Edge Function으로 서버 처리하는 것이 안전합니다.
